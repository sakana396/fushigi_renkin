- 文書 ID: IT04-PLAN

- 作成日: 2026-10-15

- 入力: [反復 3 振り返り](../it03/retrospective.md)、[SRS-001](../../02_requirements/srs.md) v0.4

## 1. 目的

反復 3 の振り返りで出た 2 つの課題を解決する（E-87）。

- K-07: 品質で威力が上がる手応えを得るには、品質の高い素材が手に入っていく進行（解放）が要る（E-85）
- K-06: 戦闘で起きたことが分からない。届かない攻撃は誤りになって番が終わらず、敵の番は一瞬で終わる（E-85、E-86）

## 2. 確かめたい仮説

| ID | 仮説 | 確かめ方 |
|---|---|---|
| H-06（再評価） | 品質で威力と効果が変わると、品質の高い製品を作る動機になる | 進行で品質の高い素材が手に入るようになったあと、品質を上げようとして素材を選んだり手作りしたりしたかを記録する |
| H-09 | 工房のランクが上がるたびにレシピや採取地が解放されると、次の目標が続き、遊び続けたくなる | 30 分ほど遊び、ランクをいくつ上げたか、次に何をしたくなったかを記録する |
| H-10 | 戦闘の画面で、各行動と操作できなかった理由が見えれば、戦闘で迷わない | 戦闘で「何が起きたか分からない」と感じた場面があったかを記録する |

| 区分 | 要求 ID | この反復での扱い |

## 4. 作らないもの

- ワールドマップと街道（FR-RD-01〜03）。採取地は採取地の場面の一覧のまま
- 物語のイベントや会話。解放のときは短いお知らせだけを出す（FR-ALC-05 に配慮）
- 装備（FR-BTL-06）、前衛が後衛を守る仕組み（FR-BTL-03）
- セーブとロード、タイトル画面
- 手作りで品質を上げる仕組みの見直し（TBD-03）

## 8. 開始前の決定事項（開発者の確認待ち）

| # | 論点 | 推奨 | 他の案 |
|---|---|---|---|
| P-01 | 進行の仕組み | **a. 工房のランク（1〜4）。依頼を納品すると「評判」がたまり、決まった量に達するとランクが上がる** | b. 施設の段階で解放する（今の施設と結びつける）。c. 戦闘の勝利数で上がる |
| P-02 | ランクで解放するもの | **a. レシピ、採取地（品質の高い素材が採れる。探索の報酬もさらに高い）、依頼（品質の条件が高く、報酬も多い）** | b. レシピだけ |
| P-03 | 品質の段階の効果と進行の関係 | **a. 効果の段階（品質 50・100・150・200）はアイテムの定義のまま。進行で品質の高い素材が手に入るようになることで、段階の効果に自然に届くようにする** | b. 段階の効果そのものを、ランクで解放する（品質 100 の効果はランク 3 から、など） |
| P-04 | 解放の知らせ | **a. ランクが上がったとき、画面の上に「工房ランク 2: ○○を作れるようになった、○○に行けるようになった」と出す。物語の文章は付けない** | b. 短い物語の文章を付ける |
| P-05 | 戦闘で起きたことの見せ方 | **a. 敵の行動を 1 つずつ短い間（0.5 秒ほど）を置いて見せ、行動したユニットと相手のマスを強調する。誤りは戦闘の画面の中に目立つように出す。届く敵がいないときは「攻撃」を押せず、「届く敵がいません。待機で番を終えます」と案内する** | b. 記録を見やすくするだけ（間を置かない） |
| P-06 | 実装の担当 | **a. Codex のクレジットが尽きているので、実装は Claude Code が起こす別のエージェント（実装担当）が行い、レビューは spec-reviewer が行う。実装とレビューを別にする原則は保つ** | b. Codex を補充して使う |
