## 5. 進め方の振り返り

### うまくいったこと

- 計画を変えたい（E-95）と言われてから、計画・SRS・設計・ADR を、それぞれレビューと開発者の承認を経て確定させてから実装に入った。工程の文書が方向転換の記録として残った
- 設計書に計算例を 31 件書き、レビューで 1 行ずつ検算したうえで、core のテストの期待値にそのまま使った。core の Issue（#86）は、テストを足すだけで直り、実装の誤りはなかった
- 地図の検証（#85）・core（#86）・本体の地図（#87）のレビューで、変異を手で試してテストの穴を見つけた（#85 は 28 通り中 15 通り、#86 は 12 通りが通り抜けた）。直したあと Claude Code も代表的な変異を入れて、検出を再確認した
- 独立した Issue（#85 と #88、#86 と #87）を別のワークツリーで並行させ、依存する Issue は前の Issue のブランチの上で先に進めた。トレーサビリティの衝突は、行ごとに列を合わせて解消した
- 手動テストのエージェントが、座標を画面に出す確認用の版をスクラッチの中で作り、位置の境界（壁で止まる位置、扉の角の補正）を数値で確かめた
- 画像素材を配布元から取得し、バイト単位の照合と SHA-256 のテストで、取り違えや改行の変換を防いだ

### うまくいかなかったこと

| 問題 | 対策 |
