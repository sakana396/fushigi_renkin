## 5. 進め方の振り返り

### うまくいったこと

- 設計のレビューで、計算例を 1 行ずつ検算させた（REV-024）。2.5 節の戦闘の流れの計算例を、そのままテストの期待値にできた
- すべての core の Issue で、レビュー担当にミューテーション（わざと誤った実装にしてテストが落ちるか）を試させた。テストの穴を毎回見つけて直せた（REV-026〜029、032）
- ui の手動テストを、別のエージェントに Windows 版で行わせた。検証用のデータのコピーを使い、本体のデータを変えずに境界と異常系まで確かめられた（REV-031、033）
- トレーサビリティの衝突を、行ごとに列を合わせる道具で解消できた

### うまくいかなかったこと

| 問題 | 対策 |
|---|---|
| 並行した Issue で、トレーサビリティとテスト仕様書の衝突が毎回起きた | 行ごとに列を合わせて解消した。状態の列は文が長くなりやすいので、最後に短く整えた |
| 画面の Issue を分けたとき、戦闘の開始を戦闘の画面より前の Issue に入れていた（#50）。戦闘の画面がないまま戦闘が始まると操作できなくなる | つなぐ作業を #51 に移した（REV-031 R-01）。画面の Issue は、遊べる単位で分ける |
| Codex のクレジットが #51 の修正の途中で尽きた | 残りは Claude Code が行った。反復 4 で Codex を使うなら補充が要る |
| 手動テストは仕様どおりに合格したが、遊ぶ人には戦闘で起きたことが分からなかった（K-06） | 手動テストに「初めて遊ぶ人が、操作の結果を画面から読み取れるか」の観点を足す |
