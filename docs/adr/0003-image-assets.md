# ADR-0003: 画像素材の導入と置き場

- 状態: 提案（案。人の承認を待つ）
- 日付: 2026-10-15
- 関連: [IT05-PLAN](../iterations/it05/plan.md) P-04・P-13、[SRS-001](../02_requirements/srs.md) CST-04・IF-08、[DES-IT05](../03_design/design-it05.md) DES-UI-14
- 変えるもの: [ADR-0001](0001-tech-stack.md) の「影響」の 3 つ目（図形と文字を中心にする）、[PLAN-001](../00_plan/project-plan.md) 2.2 の「凝ったグラフィック（図形や簡易スプライトで代用する）」

## 背景

- 反復 5 では、主人公を操作して工房と街を歩く見下ろし型の画面にする（E-95、E-96）。目標の見た目はスターデューバレーのような 2D で、地面・壁・設備・主人公が絵で見分けられる必要がある
- 今の画面は、ADR-0001 の「影響」と PLAN-001 2.2 に従い、四角と文字だけで描いている。画像のファイルはリポジトリにない
- 開発者は、見た目を「フリー素材のドット絵」にすると決めた（E-96。推奨は色の四角だった）。計画書で、CC0 の素材から選び、第一候補を Kenney にすると決めた（P-04、E-97）
- リポジトリは公開している。同梱する画像は、再配布できる利用許諾のものに限り、出典と利用許諾を記録する（CST-04）
- 画像の置き場は、`internal/ui/assets/` に置いて ui が `go:embed` すると決めた（P-13、E-97）。この ADR はその理由と決まりを記録する

## 決定

1. **画像素材を使う**。工房と街の地図（地面・壁・設備・出入り口）と主人公を、ドット絵のタイルで描く。窓（錬金、店など）の中、採取地の一覧、戦闘の画面は、今の四角と文字のままにする（反復 5 の範囲。IT05-PLAN 1 章）
2. **使ってよい素材は、CC0 1.0 のものに限る**。反復 5 で使うのは次の 2 つ

   | 素材 | 版 | 作者・配布元 | 利用許諾 | 使う物 |
   |---|---|---|---|---|
   | Tiny Town | 1.1 | Kenney、<https://kenney.nl/assets/tiny-town> | CC0 1.0（同梱の License.txt） | 草地・道・木・家の壁と屋根・木の扉・看板・屋台 |
   | Tiny Dungeon | 1.0 | Kenney、<https://kenney.nl/assets/tiny-dungeon> | CC0 1.0（同梱の License.txt） | 石の床と壁・石の扉・設備（鉢、棚、金床）・主人公 |

   - どちらも 16×16 px のタイルで、絵柄がそろっている。2026-10-15 に、配布元から取得した zip の License.txt で CC0 1.0 と確かめた
   - CC0 は、再配布・改変ができ、クレジットも要らない。それでも、出典は記録する（CST-04）
3. **置き場は `internal/ui/assets/`**。ui が `go:embed` でバイナリに埋め込む。置くのは次のファイル
   - タイルの画像: 配布物の `Tilemap/tilemap_packed.png`（タイルの間に隙間のない 1 枚の画像）を、`tiny_town.png`・`tiny_dungeon.png` の名前で置く
   - 利用許諾: 配布物に同梱の `License.txt` を、`kenney_tiny_town_License.txt`・`kenney_tiny_dungeon_License.txt` の名前で、手を加えずに置く
   - 出典の記録: `README.md`。素材ごとに、素材名と版、作者、配布元の URL、利用許諾（CC0 1.0 と、利用許諾のファイル名）、確かめた日、取り込んだファイルと元のファイル名を表にする。素材を足したり差し替えたりしたら、同じプルリクエストでこの表を直す
4. **素材を足すときの手順**
   - 取り込む前に、配布元のページと同梱の利用許諾のファイルで、CC0 1.0 であることを確かめる。CC0 でない素材（クレジットが必須、再配布の禁止など）は使わない
   - 配布物の中のスクリプトや実行ファイルは取り込まない。画像と利用許諾のファイルだけを取り込む
   - 使うタイルの番号は、設計書（DES-IT05 DES-UI-14・15）に書く
5. パッケージの依存の向き（DES-PKG）は変えない。画像を読むのは ui だけで、core・defs・defload は画像を知らない

## 理由

- **見た目の目標に届く**: 見下ろし型の地図は、地面・壁・設備が見分けられないと遊べない。色の四角でも作れるが、開発者は「フリー素材のドット絵」を選んだ（E-96）。H-11（ボタンの画面より錬金術士として遊んでいると感じるか）を確かめるにも、絵があるほうが比べやすい
- **CC0 なら公開リポジトリに入れられる**: 再配布の禁止やクレジットの条件を、素材ごとに確かめて守る手間がない。利用許諾の違反で公開を取り下げる危険もない
- **Kenney の 2 つの素材は絵柄がそろう**: Tiny Town と Tiny Dungeon は同じ作者・同じ大きさ・同じ描き方で、並べても違和感が少ない。Tiny Town だけでは、室内の床・設備・人物が足りない
- **`internal/ui/assets/` に置けば ui の中で閉じる**: 画像を使うのは ui だけである。`data`（定義データ）に置くと、`cmd` が画像を ui に渡す仕組みが要り、定義データの形式（ADR-0002）に画像の扱いが入る。反復 5 では MOD で画像を差し替えないので（IT05-PLAN 4 章）、その仕組みは要らない
- **出典を画像と同じ場所に置く**: 画像を差し替えた人が、同じフォルダの記録を直せる。記録と画像がずれにくい

## 検討した代替案

| 案 | 採用しなかった理由 |
|---|---|
| `data` に置き、`cmd` が ui に渡す（P-13 b） | MOD で画像を差し替えやすくなるが、反復 5 では作らない（IT05-PLAN 4 章）。画像の受け渡しのために ui の入口と `data` の役目が広がる。MOD で画像を扱うと決めたときに、別の ADR で置き場を見直す |
| itch.io などのフリー素材（P-04 b） | スターデューバレーに近い絵柄が多いが、再配布の禁止、クレジットの表示、商用の制限など、条件が素材ごとに違う。公開リポジトリに入れられない素材が多く、確かめる手間と危険が大きい |
| 色の四角で仮置き（P-04 c） | 画像の利用許諾の問題はないが、開発者は絵を選んだ（E-96）。地図の地形と設備を色だけで見分けるのは難しい |
| RPG Urban Pack（Kenney、CC0 1.0） | 人物に 4 方向の絵があるが、絵柄が現代の街で、錬金術士の工房に合わない |
| 1 タイル 1 ファイル（配布物の `Tiles/tile_NNNN.png`）を置く | ファイルが 264 個になる。読み込みとリポジトリの見通しが悪くなる。1 枚の画像から切り出すほうが簡単 |

## 影響

- ADR-0001 の「影響」の「MVP では図形と文字を中心にして負担を抑える」と、PLAN-001 2.2 の「凝ったグラフィック（図形や簡易スプライトで代用する）」を、工房と街の地図と主人公については、この ADR のとおり変える。凝った演出（数コマを超えるアニメーションなど）を作らないことは変えない（IT05-PLAN 4 章）。この ADR が承認されたら、ADR-0001 と PLAN-001 に、ADR-0003 で変えたことを注記する
- バイナリが画像の分だけ大きくなる（2 枚で数 KB）
- 画像の読み込みに失敗したときの誤りの扱いが ui に増える（DES-UI-14）
- 素材の取り込みは、実装の Issue で行う。この ADR の時点では、リポジトリに画像はない
- 主人公の絵は正面向きの 1 コマで、4 方向の歩く絵はない。左右は反転で表し、上下は向きの印で補う（DES-UI-17）。4 方向の絵が要ると分かったら、CC0 の素材を探し直すか、別の判断をする
