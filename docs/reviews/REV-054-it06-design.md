## 検証

- 文書だけの変更で、コードは変わっていない
- `gofmt -l .` は出力なし。`GOOS=windows go vet ./...` は成功
- `go test` は core・defload・defs・data・ui/assets・tools/tccheck が成功（ui と cmd は Linux に X11 のヘッダーがないためビルドできない）
- `go run ./tools/tccheck` は整合 OK（警告 164 件は手動テスト）
- 計算例 3.7 の F-1〜F-17 を、DES-IT05 2 章の規則（移動、当たり判定、前の帯）で 1 行ずつ検算し、すべて一致した。F-18 は一致しなかった（F-01）
- 計算例 1.3 の D-1〜D-5 と 2.3 の Q-1〜Q-15 は、DES-DAY-01・02 と DES-QST-04・05 の規則（Tick の順番、全部を空にしてから引き直す、検査の順）と一致する
- 本体の街の地図（5.4 節）は 30 × 20 で、開始位置 (10, 15) は床。区画 a〜d は 3 × 3 で、すべて開始位置から行ける。歩く距離（工房の扉・店・依頼板・出口の 6 組と、区画への参考の値 4 つ）は、BFS で計算した値と一致した
- 売値の効果は最大で合計 +35% になるが、店の品だけで作れるレシピはなく、買って売るだけで儲かる道はない。新しい依頼の報酬は、どれも同じ品を品質の条件で売った額より多い
- 日替わりの抽選は依頼用の乱数列（`rand.NewPCG(seed, 1)`）だけを使い、ゴーレムの乱数とは列が別なので、Tick の中の順番で結果は変わらない（NFR-06）
