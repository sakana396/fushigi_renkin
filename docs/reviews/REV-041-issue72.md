# REV-041: Issue #72（ui: 戦闘の出来事を順に見せる、誤りと案内を戦闘の画面に出す）のレビュー

- 対象: ブランチ `it04/72-battle-ui`（Issue #72。#71 のブランチの上に作り、#71 のマージ後に main を取り込んだ）
- 日付: 2026-10-15
- 実装: Codex（指摘の修正は Claude Code）
- レビュー: spec-reviewer（仕様適合レビュー）。Windows 版の手動確認は別のエージェント
- 承認: 不要（要求・設計・企画の文書と ADR は変更していない）
- 結果: 指摘を修正し、Windows の手動確認がすべて合格したので承認

## 検証

- `gofmt -l .` は出力なし。`GOOS=windows go vet ./...` は成功
- `go test` は core・defload・data・tools/tccheck が成功（ui と cmd は Linux に X11 のヘッダーがないためビルドできない）
- `go run ./tools/tccheck` は整合 OK（TC-IF-07-30〜42 は手動テスト）
- コードを読んで、次を確かめた
  - 出来事は 30 回の更新ずつ見せ、F11 の倍率に従わない
  - 見せている間の押す操作は、飛ばすことにだけ使われる
  - 記録は見せた出来事までを出す
  - `StartBattle` の直後も最初から見せる
  - 戦闘が終わったときは、見せ終わる（または飛ばす）→ 結果 → 採取地、の順になる
  - 出来事が 0 件のときと、出来事の途中で戦闘が終わるときも破綻しない
  - DES-UI-13 の文と、押せない表示が設計どおり
  - 反復 3 の決まり（番が変わると操作を移動に戻す、狙えるマスの黄色、勝ち負けの操作結果）を保っている
- Windows の手動確認: TC-IF-07-30〜42 の 13 件すべて合格（修正後の版で実施）。計算例（DES-IT04 2.2 節）は、`spring_cave` の敵の配置を変えたテスト用の版で、出来事の順・強調・体力・記録の行数が期待値と一致した。切り替えの間隔は 0.41〜0.58 秒（平均約 0.5 秒）で、時間 ×10 でも変わらなかった
- #71 のマージ後に main を取り込んだ。#71 の修正は工房・街の知らせとタブの位置だけで、戦闘中はタブを押せず、戦闘の画面の操作結果は 1 行なので、手動確認はやり直していない

## 指摘と対応

| # | 指摘 | 区分 | 対応 |
