# REV-024: 反復 3 の計画書・SRS v0.3・ユースケース v0.3・設計書（反復 3）のレビュー

- 対象: ブランチ `it03/plan`（PR #42。反復 3 計画書 v1.0、SRS v0.3、ユースケース v0.3（UC-11〜14）、設計書 DES-IT03 v0.2、要求抽出記録 E-79〜E-82、反復 2 振り返り v1.0、文書一覧）
- 日付: 2026-10-14
- レビュー: spec-reviewer（仕様適合レビュー。v0.1 のレビューと、v0.2 の再レビュー）
- 承認: SRS v0.3 と計画書 8 章は開発者が承認済み（E-81）。R-06・R-09・R-11 は開発者が決定（E-82）。ユースケース v0.3 と DES-IT03 v0.2 は、開発者が PR #42 をレビューしてマージし、承認した（E-83）
- 結果: 指摘を修正して承認

## 検証

- 文書だけの変更で、コードは変わっていない
- `gofmt -l .` は出力なし。`GOOS=windows go vet ./...`、`go test`（core・defload・data・tccheck）、`go run ./tools/tccheck` は成功（警告 39 件は手動のテストケース）
- DES-QLT-05 の計算例（爆弾、ハンバーガー）、行動順、2.4 節の敵の動き、2.5 節の戦闘の流れ（4 巡）、負傷の時間、納品の計算例を 1 行ずつ検算し、合っていた
- 依頼の乱数を別の列（`NewPCG(seed, 1)`）にしても、既存のテスト（TC-NFR-06-01〜03 など）は壊れない
- 既存の core（World、Inventory、gatherIntoInventory）の構造で、戦闘の報酬、納品、別の乱数列を作れる

## 指摘と対応

| # | 指摘 | 区分 | 対応 |

| R-01 | 最初の番が敵のときの StartBattle の処理が、状態遷移図と計算例で食い違う | 必須 | 最初の番が敵なら、StartBattle の中で仲間の番か戦闘の終わりまで処理すると明記した。2.5 節の 1 巡目で例を示した |
