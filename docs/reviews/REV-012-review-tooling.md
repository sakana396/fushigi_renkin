# REV-012: レビューの仕組み（サブエージェントと ID の整合検査）の導入

- 対象: ブランチ `it01/review-tooling`
- 日付: 2026-10-14
- 起案: Claude Code（反復 1 の 8 件のレビュー REV-003〜011 の結果から）
- 承認: 開発者本人（「両方作って進めて」）
- 結果: 承認

## 背景

反復 1 のレビューで見つかった問題を分類すると、判断が要るものと、機械的に判定できるものに分かれた。

| 種類 | 実例 | 担当 |
|---|---|---|
| 設計書の別の箇所から導かれる制約の見落とし | REV-006（0 除算、多重度） | サブエージェント |
| テストの期待値が実装の動作から作られている | REV-010（生産サイクル） | サブエージェント |
| ゲームとしてのバランスの穴 | REV-009（買って売るだけで儲かる） | サブエージェント |
| ユースケースの代替フローの漏れ | REV-011（再使用待ちの残り時間） | サブエージェント |
| 並列作業によるテストケース ID の重複・不整合 | REV-009 | CI の検査 |

範囲外の実装、設計 ID のコメント、テストケース ID の記載、担当行だけのトレーサビリティ更新は、8 件とも実装者が守れていたため、レビューの重点から外した。

## 決定

1. **サブエージェント `spec-reviewer`**（`.claude/agents/spec-reviewer.md`）: 読み取り専用。上の 4 観点を重点に見て、指摘ごとに「設計どおりへの修正」か「設計の変更（人の承認が必要）」かを判定し、レビュー記録の下書きを返す
2. **ID の整合検査 `tools/tccheck`**: テスト仕様書の定義の重複、テストコード・トレーサビリティにあってテスト仕様書にない ID、トレーサビリティにない ID を誤りとして検出する。CI で実行する。テストコードでは、1 つのテストケースを複数のサブテストで確かめるための ID の重複を許す

## 検証

- `tools/tccheck` の単体テスト TC-QA-02-01〜04 は成功
- 現在のリポジトリに対して実行し、誤り 0 件。警告 11 件はすべて手動のテストケース（TC-IF-01、02、TC-FR-MOD-04-10）
