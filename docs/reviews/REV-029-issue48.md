## 検証

- `gofmt -l .` は出力なし。`GOOS=windows go vet ./...` は成功
- `go test` は core・defs・defload・tools/tccheck が成功。依頼のテストは 20 回くり返しても結果が同じ
- `go run ./tools/tccheck` は整合 OK
- `Quests [3]string`、別の乱数列 `rand.NewPCG(seed, 1)`、ID の昇順と `IntN`、位置 0・1・2 の抽選、候補が 3 件より少ないとき、納品後の入れ替え、検査の順、試しの写しの上での消費、品質の低い順の消費、設計書 3.3 節の計算例が、設計書と一致することを確かめた
- 依頼の抽選が本体の乱数を進めないこと（TC-NFR-06-31）、失敗した納品が依頼の乱数を進めないこと（TC-NFR-06-32）を確かめた
- ミューテーション: 修正前は 20 通りのうち、納品後の入れ替えをなくす、別のアイテムも納品に使う、あふれの検査を `>=` にする、の 3 通りが通り抜けた。修正後、Codex が R-01〜R-05 に対応する 5 通りの検出を確かめ、Claude Code も入れ替えをなくす変異を TC-FR-ECO-05-10 が検出することを再確認した

## 指摘と対応

| # | 指摘 | 区分 | 対応 |
|---|---|---|---|
| R-01 | 納品後に依頼板が入れ替わることを、どのテストも見分けられない（TC-10 のシード 42 では補充が納品前と同じ ID になる） | 設計どおりへの修正 | TC-10 を補充が変わるシードにし、納品前と違うことを前提として確かめるようにした。TC-03 の期待結果を「同じ依頼が再び入る（候補が 1 件のため）」と正確にした（Codex） |
| R-02 | 依頼のアイテム以外の在庫を使わないことを確かめていない | 設計どおりへの修正 | 別のアイテムを高品質で混ぜ、残ることと、不足の判定に数えないことを確かめた（TC-FR-ECO-05-11 など）（Codex） |
| R-03 | TC-07 がお金がちょうど上限になって成功する側を試していない | 設計どおりへの修正 | 成功する側を足した（Codex） |
| R-04 | TC-04 の前提とテストのデータが合わない | 設計どおりへの修正 | テストで在庫を入れ、範囲外でも在庫が減らないことを確かめた（Codex） |
| R-05 | 目録にない ID が依頼板にあると、何も使わずに報酬 0 で成功する | 設計の範囲内（任意） | `Catalog.Quest` で引き、見つからなければ `ErrUnknownID` を返すようにした（Codex） |
| R-06 | #46 と衝突する | 情報 | 後からマージする側で解消する |
